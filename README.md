# Meridian Bank – Manual Software Testing Project

A practical manual black-box testing project focused on validating the functionality, data integrity, usability, and basic security of a demo web-based banking application.

## Project Overview

This project involves testing Meridian Bank (Build 2.4.1) against its stated requirements and expected banking behavior. The goal is to execute structured test cases, identify defects, and document testing results.

## Testing Scope

- User Registration
- Login, Logout & Remember Me
- Account Lockout & Session Timeout
- Dashboard & Account Details
- Deposit, Withdrawal & Fund Transfer
- Bank Statements & CSV Export
- Beneficiary Management
- User Profile & Password Management
- Admin Panel & Customer Management
- Role-Based Access Control

## Testing Methodology

- Functional Testing
- Positive & Negative Testing
- Boundary Value Analysis
- State Transition Testing
- Data Integrity Testing
- Basic Security Testing
- UI & Usability Testing
- Regression Testing

## Test Documentation

**Meridian_Test_Cases.xlsx**

The Excel workbook contains four sheets:

1. **Read Me:** Testing instructions, execution guidelines, status definitions, priorities, and test data.
2. **Summary:** Automatically calculated test execution statistics and defect counts.
3. **Test Cases:** Test scenarios, preconditions, test steps, expected results, actual results, execution status, and bug IDs.
4. **Bug Reports:** Defect IDs, reproduction steps, expected vs. actual results, severity, priority, and defect status.

**Meridian Bank – Test Plan.pdf**

Includes testing objectives, scope, test approach, environment, entry and exit criteria, defect management, risks, and testing schedule.

## Test Execution Process

- Reset application data before test execution.
- Execute High-priority test cases first.
- Compare actual results against expected results.
- Record Pass, Fail, or Blocked status.
- Document failed scenarios in the Bug Reports sheet.
- Track execution progress through the Summary sheet.
